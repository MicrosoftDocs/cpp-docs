# Warning C26824

> Postcondition for null pointer '*variable*' requires it to be non-null (lifetime.1)

## Remarks

Dereferencing a null pointer is a frequent problem in C and C++. We have several checks to deal with such problems. See this [blog post](https://devblogs.microsoft.com/cppblog/improved-null-pointer-dereference-detection-in-visual-studio-2022-version-17-0-preview-4/) for a comparison. When the analysis engine determines that a function produces a null pointer despite a SAL postcondition that requires a non-null value, it emits warning C26824. The contract may apply to a return value, such as `_Ret_notnull_`, or to an output parameter, such as `_Outptr_` or a conditional `_When_(..., _Outptr_)` annotation. You can also enable [C26825](../code-quality/c26825.md) to report values that might be null. This check only works on functions annotated using [SAL annotations](../code-quality/understanding-sal.md).

## Example

```cpp
void postcondition_conditional(bool b, _When_(b == true, _Outptr_) int** p)  { 
    if (b == true) 
        *p = nullptr; // C26824 warning 
} 
```

To solve this warning, make sure the annotated function produces a non-null return value or output value on every path where the contract applies. Or, change the annotations to reflect the behavior of the function.
